# 规划审阅记录

日期：2026-10-16。审阅对象为 [原计划](archive/EXECUTION_PLAN_2026-10-14.md)，修订结果见 [当前执行计划](../EXECUTION_PLAN.md)。本轮审阅前目录只有原计划，没有工程实现或 Git 历史。

结论：总体路线可保留，但原计划主要描述“选什么模块、分几阶段”，缺少跨模块契约、兼容性证据、验收口径和失败后的具体行动。当前修订将它转换为可分派、可检查、可暂停特定依赖的实施任务。**规划可执行不代表硬件兼容和性能目标已验证。**

## 2. 保留的合理选择

继续使用 Ubuntu 24.04、C++17/CMake、libpulse 兼容接口、RKNN ASR、RKLLM Qwen、CPU VAD/TTS/KWS；第一阶段先做按键 MVP，之后再做唤醒/语音打断。AEC 根据误触发测量决定，ROS 和容器不进入 MVP。运行库使用项目私有目录，保留模型清单与许可证，常态不保存连续录音。

原计划已经提醒不盲目升级驱动、注意蓝牙带宽和缓存、记录模型哈希。本轮把这些提醒转成具体关口和验收，而没有把候选路线误写为确定可行。

## 3. 优先级与可执行分支

1. **先完成工具链和 SDK 矩阵。** 板端当前缺开发包，模型需要落实配套预转换产物，均有明确任务；仅“安装最新版”不能解决版本组合问题。
2. **按已明确的要求取得 M0 证据。** 先解决当前 0.9.7 低于 RKLLM 1.3.1 所要求的 0.9.8 这一前置条件，再分别确认小模型与目标模型；驱动适配不能留到集成末期。
3. **音频和 CPU TTS 可独立推进。** 用户已完成蓝牙连接与同时录放，不再作为兼容性调查的阻塞项。
4. **共驻验证先于全链路。** 正式写实时状态机前先确认模型/库能共存且资源足够。
5. **MVP 必须可取消、可恢复。** 唤醒和 AEC 可后移，错误恢复与有界资源不能后移。

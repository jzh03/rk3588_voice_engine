# 验收用例与测量规则

日期：2026-10-14。对应 [执行计划](../EXECUTION_PLAN.md) v1.6。A01～A14 全部为**待实施的应用验收**；用户已完成的蓝牙连接与系统同时录放基线 B01 不在本表重复验收。当前实现进度见执行计划；配置与 mock 检查不代表实机应用验收通过。

## 1. 通过规则

每个用例必须有代码版本、配置哈希、模型清单哈希、实际 SDK/驱动版本、测试输入、结果和失败原因。`not_run`、`blocked`、`failed` 不计为通过。文档中的数值是初始工程目标，不是本轮测得的性能。

崩溃、OOM、错误设备播放、旧轮次串音、数据无界增长是硬性失败。数值目标需调整时保留原目标、实测值、原因和负责人确认；不能只改阈值来消除失败。M1 要求 A01～A10，M2 增加 A11/A12，M3 增加 A13/A14。

## 3. 固定语料及内容评分

建立 20 条 2～8 s 的普通说话语音：普通中文 8 条、数字/日期 5 条、短问句 4 条、中英混说 3 条。先使用干净文件隔离模型问题，再用耳机录制的版本测试应用，不混用为同一数据集。另设无声、噪声、15 s 长语音等边界样本，不塞进正常准确率的分母。

每条清单包含 `sample_id`、文件路径/SHA-256、采样率、时长、参考转写、归一化转写、关键词、类别、录制条件和预期行为。测试集与量化校准集分离，不用测试答案调阈值后仍宣称独立验收。

CER = `(替换 + 删除 + 插入) / 参考字符数`。中文统一全半角、去标点和空白；大小写/数字归一化规则写入版本化脚本，同时保存原文，不能把数字读错归一化掉。混合英文另报关键词准确率；空参考的无声样本只判断是否误识别，不计算 CER。

“18/20”指至少 18 条语音中的**全部预标注关键词**正确；每一批均达标，不从三批中挑最好一次。按普通中文、数字/日期、中英分别列结果，避免总分掩盖特定失败。

LLM 短答评分由实施者逐项记录“切题、无明显事实矛盾、符合短答范围、无思考/控制标记泄漏”，疑难项交用户复核；不做泛化知识能力承诺。实时天气等无数据来源问题应说明没有实时信息，不能编造联网结果。TTS 声音喜好由用户选择，语音是否有效和数字是否读对另作客观记录。

## 4. 时间点、口径与统计

程序时间均用 `CLOCK_MONOTONIC` 或等价单调时钟。UTC/本地日期仅用于定位日志，不用于计算耗时。

| 字段 | 含义 |
|---|---|
| `speech_end_ns` | 本轮最后一个有效语音采样点对应的单调时钟估计 |
| `endpoint_ns` | VAD/手动 stop 确认发言结束的时刻 |
| `asr_final_ns` | 最终识别文本可用 |
| `llm_submit_ns` / `llm_first_token_ns` | 提交请求 / 首 token 到达 |
| `speakable_text_ns` | 过滤后第一段可播报文本就绪；它可能晚于首 token |
| `tts_submit_ns` / `tts_first_pcm_ns` | 提交首段合成 / 首段 PCM 可用 |
| `playback_submit_ns` | 第一次向音频服务提交本轮 PCM |
| `cancel_requested_ns` / `old_pcm_stopped_ns` | 请求取消 / 停止旧 PCM 提交 |
| `flush_ack_ns` / `model_stopped_ns` | 音频服务确认清空 / 模型任务结束 |

`endpoint - speech_end` 是端点等待；`asr_final - endpoint` 是端点后的 ASR 尾部耗时；LLM TTFT、文本分段等待、TTS 首音频和播放等待分别记录。RTF = 处理用时 / 对应音频时长。不能拿 tokens/s 直接代替端到端体验。

**实际听到的时间：**用同一外部录音同时采集用户发言和耳机声音，按试验 ID 标注最后语音、回答起声、取消动作和尾音；声明测量分辨率。耳机听筒可临时贴近测量麦克风，避免人为按秒表当精确 P95。服务 timing 信息只能作估算，记录 `measurement_method=server_estimate`；真正声学记录使用 `external_audio`。两者分别统计，不混用不同机器的未同步时钟。缺少声学记录时，保留性能待验证状态。

20 个短问题 ×3 批使用固定模型/模板/上下文条件、最多 64 输出 tokens、相同 profile 和采样率，先预热再随机化顺序。正常配置仍支持最多 128 输出 tokens。报告 N、成功/失败/超时数、P50/P95/max、模型加载时间和内存峰值。P95 使用升序后的第 `ceil(0.95*N)` 个值；60 个样本取第 57 个。失败不能从汇总中消失：时延分位数标明只针对成功样本，同时列完整失败率；A10 通过要求整批无失败。

## 5. 资源与长稳判定

每秒记录进程 RSS（分进程时求和）、可读时的 PSS、MemAvailable、swap-in/out、队列深度、线程/FD 数、CPU 占用及温度/频率。NPU 内存若有受限指标，标记不可读，结合系统余量及 runtime 日志判断，不把 RSS 当成所有 NPU 内存。

1 h 长稳先允许 10 min 预热。以第 10～20 min 的 RSS 中位数为基线，第 50～60 min 的中位数增长不得超过 `max(100 MiB, 基线的 5%)`；同时检查后 40 min 是否持续上升且未趋稳。超过阈值或存在持续增长时分析缓存/句柄释放并延长验证，不能只凭起止两点判定无泄漏。MemAvailable 目标 ≥1.5 GiB，空闲磁盘 ≥3 GiB；报告测试期间的降频和延迟变化。

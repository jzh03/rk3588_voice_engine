## 4. 时间点、口径与统计

程序时间均用 `CLOCK_MONOTONIC` 或等价单调时钟。UTC/本地日期仅用于定位日志，不用于计算耗时。

| 字段 | 含义 |
|---|---|
| `speech_end_ns` | 本轮最后一个有效语音采样点对应的单调时钟估计 |
| `endpoint_ns` | VAD/手动 stop 确认发言结束的时刻 |
| `asr_final_ns` | 最终识别文本可用 |
| `llm_submit_ns` / `llm_first_token_ns` | 提交请求 / 首 token 到达 |
| `speakable_text_ns` | 过滤后第一段可播报文本就绪；它可能晚于首 token |
| `tts_submit_ns` / `tts_first_pcm_ns` | 提交首段合成 / 首段 PCM 可用 |
| `playback_submit_ns` | 首个本轮语音PCM被播放后端接受；当前实时实现为应用入队的软件观测 |
| `cancel_requested_ns` / `old_pcm_stopped_ns` | 请求取消 / 停止旧 PCM 提交 |
| `flush_ack_ns` / `model_stopped_ns` | 音频服务确认清空 / 模型任务结束 |

`endpoint - speech_end` 是端点等待；`asr_final - endpoint` 是端点后的 ASR 尾部耗时；LLM TTFT、文本分段等待、TTS 首音频和播放等待分别记录。RTF = 处理用时 / 对应音频时长。不能拿 tokens/s 直接代替端到端体验。

**实际听到的时间（原方法留作条件具备时参考，本轮不执行）：**用同一外部录音同时采集用户发言和耳机声音，按试验 ID 标注最后语音、回答起声、取消动作和尾音；声明测量分辨率。耳机听筒可临时贴近测量麦克风，避免人为按秒表当精确 P95。服务 timing 信息只能作估算，记录 `measurement_method=server_estimate`；真正声学记录使用 `external_audio`。两者分别统计，不混用不同机器的未同步时钟。缺少声学记录时，保留性能待验证状态。

启用 `audio.playback_keepalive` 时，同时报告开关、启动/空闲/重连前后sink状态、独立保活欠载和语音欠载。需验证首次回答及长于设备空闲周期后的回答开头、取消不残留旧语音、正常drain/历史提交不被保活阻塞、退出释放流；服务RUNNING/uncork确认不等于耳机声学通过。当前候选为保活true、前置静音0，局部回归与实听结果见[实机进度](environment.md#56-p4-02-耳机实机验收进行中)。若另启用 `audio.playback_lead_in_ms`，其等待仍计入A10且不扣除；前缀属于语音generation并受取消flush覆盖，跨会话的独立保活只包含零PCM。静音或语音样本的软件提交事件均不能代替外部声学起声；验收门槛与正式样本数不变。

启用 `tts.prebuffer_ms` 时另报告真实音频储备目标、首段生成/首次放行/首PCM提交的各时刻，以及原生槽数/采样峰值；SDK临时输出与应用PCM队列分别计量。检查短句/空EOS不阻塞、取消清空预取且无旧PCM、后续合成与送音可重叠，并以播放欠载和人工/外部声学记录核对连续性。新增起播等待全额计入A10。调整 `tts.target_chars` 时保持起播储备一致，使用同一冻结文字/到达时间线交错重复比较；检查原文完整、长数字/日期/英文词不被软目标拆开，另行试听短段语调和句尾。不同LLM回答不能直接作为同文本时延对照；严格比较沿用冻结token时间线，实机有限样本不外推为所有文本负载均连续。

调整 `tts.speed` 与 `tts.boundary_lookahead_chars` 时，每次对照只改变一项，记录各段边界、音频长度、合成耗时、首PCM提交、语音/保活欠载及用户听感。自动化原文一致和零欠载不能代替语调、词内停顿与接句自然度试听。边界前瞻的实际文本等待也计入A10，不能从首音时延中扣除。改变已冻结候选的速度或分段后，正式实机批次另存候选身份，不把旧配置完成的轮次拼成新配置的20轮；旧结果和失败保留。

启用 `tts.sentence_mode` 时，需分别检查首段可以在分句标点提前输出、后续完整句不会按相同短长度拆分、已排队文字不受过期定时器误切、min/max/EOS/数字日期/UTF-8和新轮复位。测试固定文本及到达时间线，报告分段、首PCM等待与欠载；在此基础上再复验四模型及耳机。若自然分段增加首音等待或欠载，应保留回归失败和未启用状态，不能以词完整或试听预生成文件替代实时供音通过。

启用 `tts.join_short_sentences` 时，固定速度、原文、到达时间线与预缓冲对照；核对分段和原文不变、段尾语气/引号/数字小数及非法UTF-8检查保留，禁止为凑段增加文字等待或扩张边界。记录实际前端文本、首PCM、欠载和内部低能量间隔；后者只是停顿代理，不能替代丢字/读音/自然度试听。当前0.9与合并开关是新候选，旧正式五轮独立保留，见[环境§56.20](environment.md#5620-参考项目标点控制与有界段内短句合成)。

本轮按2026-10-27用户确认，20个固定短问题各1次预热软件测量，3次进程冷启动单列；保持当前模型/模板/会话清理条件及128输出token上限，先预热再按固定种子随机化顺序。原20短题×3批、64token/60样本基准保留为历史参考，本轮不自动扩测或调参。报告N、成功/失败/超时、P50/P95/max、加载时间和内存峰值；P95取升序第ceil(0.95*N)个值，20个成功样本取第19个。失败完整保留，分位数注明成功样本分母；软件估算与真实耳机声学结果分开；当前声学目标按本页测量限制保留未测，不以软件结果冒充声学通过。独立范围与结果见[本轮复核](../tests/fixtures/p4-automation-review.json)。

## 5. 资源与长稳判定

每秒记录进程 RSS（分进程时求和）、可读时的 PSS、MemAvailable、swap-in/out、队列深度、线程/FD 数、CPU 占用及温度/频率。NPU 内存若有受限指标，标记不可读，结合系统余量及 runtime 日志判断，不把 RSS 当成所有 NPU 内存。

1 h 长稳先允许 10 min 预热。以第 10～20 min 的 RSS 中位数为基线，第 50～60 min 的中位数增长不得超过 `max(100 MiB, 基线的 5%)`；同时检查后 40 min 是否持续上升且未趋稳。超过阈值或存在持续增长时分析缓存/句柄释放并延长验证，不能只凭起止两点判定无泄漏。MemAvailable 目标 ≥1.5 GiB，空闲磁盘 ≥3 GiB；报告测试期间的降频和延迟变化。
